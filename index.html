Encrypted memory and cache for AI agents, in one file.

MNemo gives an agent durable memory and a cache for expensive calls, inside a single encrypted .mnemo file. There's no server or vector database to run. Copy the file and the memory comes with it.

What you get

Memory and a cache, without the infrastructure

Most agent memory means running a separate vector service: another thing to deploy, and another place for secrets to leak. MNemo treats memory like SQLite treats data. It's a file.

One portable file

Memories, cache, index, write-ahead log and snapshot history all live in one .mnemo file. A plain copy is a complete, consistent backup.

Encrypted at rest

Every 8 KiB page is sealed with AES-256-GCM under a key derived with Argon2id. Changing the passphrase re-wraps one key; the data is never rewritten.

Recall built for agents

Four memory types, ranked on similarity, recency, importance and how often a memory gets used. Per-agent scoping and expiry built in.

A cache for expensive calls New

Cache LLM responses, tool outputs and API calls by exact key, or match near-identical prompts by meaning. Namespaces, expiry and size limits included.

MCP server built in New

mnemo serve --mcp exposes memory and cache as tools to Claude Desktop, Cursor or any MCP client.

Crash-safe writes

Each commit goes through a write-ahead log with a single fsync. Kill the process mid-write and the file recovers cleanly next time it opens.

Point-in-time restore

Every commit is a snapshot. Roll back to any past transaction or moment, and roll forward again if you change your mind.

Safe to share New

One writer, many readers, enforced with OS file locks. A second writer is turned away instead of corrupting the file.

For agents

Plug it into Claude, Cursor or any MCP client

Point your MCP client at a .mnemo file and the agent gets memory and caching as ordinary tools. The passphrase comes from an environment variable, never a tool argument.

Quick start

Memory and caching in a few lines

The same engine behind every surface. These examples use the current release, v0.4.1.

import mnemo
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2")
def embed(text):
    return model.encode(text, normalize_embeddings=True).tolist()

with mnemo.open("agent.mnemo", "a long passphrase", dimensions=384) as db:
    # Durable memory
    db.remember("the user prefers dark mode", "semantic",
                embed("the user prefers dark mode"), importance=0.8)
    for hit in db.recall(embed("which theme does the user like?"), top_k=5):
        print(round(hit["score"], 3), hit["content"])

    # Cache an expensive call
    prompt = "Summarize the release notes"
    hit = db.cache_get("llm", prompt)
    if hit is None:
        answer = call_llm(prompt)                # your LLM call
        db.cache_put("llm", prompt, answer, ttl_secs=3600)
    else:
        answer = hit["value"].decode()
use mnemo::{CachePutOpts, Memory, MemoryType, Mnemo, MnemoConfig, RecallRequest};

fn main() -> mnemo::Result<()> {
    let cfg = MnemoConfig { dimensions: 3, ..Default::default() };
    let mut db = Mnemo::create("agent.mnemo", "a long passphrase", cfg)?;

    db.remember(
        Memory::new("the user prefers dark mode", MemoryType::Semantic, vec![0.1, 0.2, 0.9])
            .with_agent("assistant-1")
            .with_importance(0.8),
    )?;
    db.cache_put("llm", "prompt-42", br#"{"answer":"..."}"#,
        CachePutOpts { content_type: "json".into(), ttl_secs: Some(3600), cost_hint_ms: None })?;
    db.flush()?; // one atomic, crash-safe commit

    for hit in db.recall(&RecallRequest::new(vec![0.1, 0.2, 0.9]).top_k(5))? {
        println!("{:.3}  {}", hit.score, hit.memory.content);
    }
    Ok(())
}

$ mnemo cache put agent.mnemo --ns llm --key prompt-42 --value '{"answer":"..."}' --content-type json --ttl 3600
$ mnemo cache get agent.mnemo --ns llm --key prompt-42

$ mnemo snapshots agent.mnemo                      # every commit is restorable
$ mnemo restore agent.mnemo --to-txn 12

$ mnemo serve --mcp agent.mnemo                    # expose it to MCP clients

Multi-signal recall

Ranked on more than similarity

An agent needs the right memory, not just the closest vector. Every candidate is scored on four signals, with weights you can set per query.

score =
α · similarity

How close the meaning is: cosine, dot product or L2.

β · recency

Fades exponentially, with a 7-day half-life by default.

γ · importance

A 0–1 weight set when the memory is stored.

δ · ln(1 + uses)

A boost for memories the agent keeps coming back to.

Episodic

What happened: conversation turns and events. Sessions promote their turns here when they close.

Semantic

What's known: facts about the user, the project and the world.

Procedural

How to behave: preferences, rules and working conventions.

Working

Right now: the current session's scratchpad, kept or discarded when it ends.

Agent-first

Every file introduces itself

Hand an agent a .mnemo file and its passphrase, and one command tells it what the file is: which embedding model it expects, the conventions used, and any notes the author left. No separate README required.

  • Self-describing. A manifest stored inside the file, printed by mnemo about or db.about().
  • Ready from creation. mnemo init adds a starter manifest so new files are never blank.
  • Same everywhere. The Rust library, Python package, CLI and MCP server share one engine and one behaviour.

Security & reliability

Private by default, tamper-evident on disk

Without the passphrase the file is opaque, and changed bytes are detected rather than silently trusted.

  • Pages are pinned to their position. A valid encrypted page moved to another slot fails authentication.
  • The header is sealed. Pointing it at an older catalog is caught on open as tampering.
  • No password oracle. A wrong passphrase and a damaged key look identical.
  • Tested hard. Fuzzed parsers, property tests with simulated crashes, and a dependency audit on every change.
  • No unsafe code. The core crate forbids it outright.
  • Verifiable releases. PyPI packages are published from CI with signed provenance (Trusted Publishing).

Out of scope, stated plainly: anyone with write access can still delete or truncate the file, swapping in an older valid copy of the whole file can't be detected from inside it, and anyone who has the passphrase is the owner. Read the full security model.

Performance

Measured, not promised

We only publish numbers we've measured. Today that's a small baseline; benchmarks at 100,000 and 1 million memories are the next milestone, and the results will be posted here.

~35 ms
Open a file and run a top-10 recall
Python, release build, production key derivation. Small 31-memory file, v0.1.0 baseline.
~31 ms
Store a memory and commit it to disk
Includes computing the embedding. Same file and baseline.
100K–1M
Memories: benchmarks in progress
Recall latency, write throughput, file size and cache speed, on a documented reference machine.

Opening a file runs Argon2id on purpose: it's what makes guessing the passphrase expensive. Long-running processes such as the MCP server or a Python app open the file once, so each later call skips that cost.

Roadmap

Where MNemo is headed

Built in the open, one reviewed release at a time. Full history in the changelog.

Shipped v0.4.x

  • Result cache: exact keys and similar prompts
  • MCP server for Claude, Cursor and other clients
  • File locking and read-only opens
  • Fuzzing, property tests and dependency audits in CI
  • Python package caught up with the engine: cache tuning, rekey, compaction
  • Automated releases, with signed provenance on PyPI

Next v0.5.0

  • Plain text in and out from Python, the CLI and MCP; MNemo calls your embedding model
  • A check that the file is used with the embedding model it was built with
  • Rejects empty (all-zero) vectors that would pollute search
  • Then, in v0.5.x: an optional built-in local embedding model

After that planned

  • Benchmarks at 100K–1M memories, then speedups
  • Keyword search combined with meaning-based search
  • Smaller files: compressed text and vectors
  • Smarter memory: merge duplicates, summarise sessions, link related memories, forget stale ones
  • A Node.js package and framework integrations
