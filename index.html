Why

Every session starts from zero

MNemo doesn't compete with vector databases. It competes with CLAUDE.md and a notes folder.

Yesterday is gone

Decisions, conventions and the fix that finally worked disappear when a session ends or gets compacted, unless you paste them back in.

Hosted memory has a price

Memory services want an account, an API key, and your project's context on their servers.

MNemo is a file

It lives inside your repository's .git folder, encrypted, shared by every worktree and never committed. It runs on your machine and is free.

How it works

Hooks load it, tools use it, hooks save it

mnemo onboard adds three hooks, an MCP server and a short guide to each client it finds. You don't change how you work.

session start

The agent is briefed

A hook gives it the guide's short card, the project's notes, where work stands, and the memories most related to the task. 8,000 bytes by default, so it never floods the context.

while it works

It recalls and remembers

Through MCP tools: recall before a task, remember for what will matter later. A fact saved under a key replaces its old version, and history is kept.

compaction · end

The session is saved

Into its own thread, without tool output (only its size) and with known secret shapes such as tokens and keys blanked. A best effort, not a guarantee.

Three layers

Start with memory. The rest is there when you need it.

One file, three things it does for you, each one built on the one before.

1 · Memory you can search

Every session is saved and searched by meaning and exact names, so "why did we decide that?" is one recall. Facts saved under a key replace their old version and keep their history.

2 · Agents sharing work

A planner, a worker and a reviewer in Claude Code, Cursor or a terminal share tasks, an inbox, claims and review findings through the same file. mnemo inspect lets you watch.

3 · The engine underneath

AES-256-GCM on every page, a write-ahead log, restorable snapshots, a built-in local model, about 1.5 KB per memory on disk. The same engine runs in your own apps, on desktops and phones.

What you get

Everything runs on your machine

No vector database, no service to deploy, no API to call. MNemo treats memory the way SQLite treats data.

One file per project

Memories, past sessions, the search index and snapshot history in one .mnemo file. A plain copy is a complete backup.

Encrypted, no passphrase

Every page is sealed with AES-256-GCM. The key is generated and kept in your OS keychain, and a recovery code opens the file on another machine.

A local model

Text is embedded on your CPU by a small built-in model, fetched once (91 MB) and checked by SHA-256 before every load. No embedding API, no key.

Facts that change

Save a fact under a key, like decision.release-order, and the new version replaces the old one in recall. Every version stays in its history.

Recall that finds names

Meaning and keywords together, so exact identifiers like snapshot_list or v0.10.0 are found, and past sessions can be searched by meaning.

Small context first

Every read takes a byte budget, so small local models and long sessions get the most relevant memories, not all of them.

Agents coordinate through it

Run a planner, a worker and a reviewer in Claude Code, Cursor or a terminal. They share a task queue, an inbox and claims through the same encrypted file. You run the agents; they coordinate through MNemo.

See what it remembers

mnemo inspect opens the file read-only in your browser, with search and each fact's history. mnemo export --git gives a diff-clean text copy.

Security

Private by default, tamper-evident on disk

Without the key the file is opaque, and changed bytes are detected rather than silently trusted.

  • Pages are pinned to their position. A valid encrypted page moved to another slot fails authentication.
  • The header is sealed. Pointing it at an older catalog is caught on open as tampering.
  • Safe to copy and keep writing. Every writing session uses a fresh random nonce prefix, so diverged copies never reuse nonces.
  • Checked installs. The install script verifies each binary's SHA-256 and, when gh is signed in, GitHub's build attestation for the release's tag. PyPI packages carry signed provenance.
  • Tested hard. Fuzzed parsers, property tests with simulated crashes, a dependency audit on every change, and no unsafe code in the core.

Stated plainly: the keychain keeps the key out of config files, backups and screen shares, not away from programs running as you. Anyone with write access can delete the file, and an older copy of the whole file can't be detected from inside it. Memories your agent recalls go into its context, and so to its model provider. Performance

Measured, not promised

We only publish numbers we've measured. These are from v0.11.0 on an Apple M1 Pro (release build, 384-dimension vectors, about 300 bytes of text per memory). See the full results.

~3 ms
Open a 10K-memory file
With a key from the OS keychain: 0.4 ms at 1K memories, 30 ms at 100K. A passphrase adds ~15 ms for Argon2id, slow on purpose so guessing is expensive.
~2.5 ms
Search, 100K memories
Finds 98% of the true top 10 at the default settings. 2.2 ms at 10K and 0.2 ms at 1K, where every search is exact.
~1.5 KB
Disk per memory
About 6 times smaller than before v0.11's format. Memories share pages, vectors are stored at half precision, and week-old session turns are compressed. Our own brain: 18,908 memories in 33 MB.

Also a library

Memory and a cache for your own agents

The same engine runs inside your app, in Python, Rust, Swift and Kotlin, with a result cache for LLM and tool calls. These examples use v0.18.1. Phone guides: Swift and Android.

pip install mnemo-enginecargo add mnemo-engine io.github.toarchkumar:mnemo-androidtoarchkumar/mnemo-swift 
import mnemo_engine

with mnemo_engine.open("agent.mnemo", "a long passphrase", dimensions=384) as db:
    db.use_builtin_embedder()   # a small local model, fetched once; or set_embedder(fn, ...)

    # Durable memory, plain text in and out
    db.remember_text("the user prefers dark mode", "semantic", importance=0.8)
    for hit in db.recall_text("which theme does the user like?", top_k=5):
        print(round(hit["score"], 3), hit["content"])

    # A fact that changes: the key replaces the old version, history is kept
    db.remember_text("the current release is v0.18.1", "semantic", key="current-release")

    # Cache an expensive call
    prompt = "Summarize the release notes"
    hit = db.cache_get("llm", prompt)
    if hit is None:
        answer = call_llm(prompt)                # your LLM call
        db.cache_put("llm", prompt, answer, ttl_secs=3600)
    else:
        answer = hit["value"].decode()
use mnemo_engine::{CachePutOpts, EmbedCmd, EmbedderIdentity, MemoryType, Mnemo, MnemoConfig, RecallRequest};

fn main() -> mnemo_engine::Result<()> {
    let cfg = MnemoConfig { dimensions: 384, ..Default::default() };
    let mut db = Mnemo::create("agent.mnemo", "a long passphrase", cfg)?;

    // Any program that turns text into vectors (see examples/embedder_server.py)
    let id = EmbedderIdentity {
        name: "sentence-transformers/all-MiniLM-L6-v2".into(), dimensions: 384, normalize: true,
        ..Default::default()
    };
    db.set_embedder(EmbedCmd::new("python3 embedder_server.py", id)?)?;

    db.remember_text("the user prefers dark mode", MemoryType::Semantic)?;
    db.cache_put("llm", "prompt-42", br#"{"answer":"..."}"#,
        CachePutOpts { content_type: "json".into(), ttl_secs: Some(3600), cost_hint_ms: None })?;
    db.flush()?; // one atomic, crash-safe commit

    let req = RecallRequest::from_text(db.embedder().unwrap(), "which theme does the user like?")?.top_k(5);
    for hit in db.recall(&req)? {
        println!("{:.3}  {}", hit.score, hit.memory.content);
    }
    Ok(())
}

$ mnemo about agent.mnemo                          # what is this file and how do I use it?
$ mnemo remember agent.mnemo --text "the user prefers dark mode" --importance 0.8
$ mnemo recall   agent.mnemo --text "which theme does the user like?" --top-k 5

$ mnemo cache put agent.mnemo --ns llm --key prompt-42 --value '{"answer":"..."}' --content-type json --ttl 3600
$ mnemo cache get agent.mnemo --ns llm --key prompt-42

$ mnemo snapshots agent.mnemo                      # every commit is restorable
$ mnemo restore agent.mnemo --to-txn 12

$ mnemo mcp install --client claude-desktop agent.mnemo   # add it to an MCP client, no secret in the config

Roadmap

Built in the open, one reviewed release at a time

Shipped recently v0.13 – v0.18

  • Agents coordinating on one machine: a task queue with dependencies, an inbox and claims, in the same encrypted file
  • Review findings kept in the brain, and a backup of it you can commit to git
  • One-command setup for Claude Code and Cursor, with hooks that load and save the memory, and an install script that checks what it downloads
  • Keys generated and kept in the OS keychain, with a recovery code; a built-in local embedding model
  • Recall by meaning and keywords together, with exact identifiers matched
  • A memory inspector in your browser, now with your agents' findings and tasks, and a git-friendly export
  • iOS and Android packages
